Version 1.2.2 fixes NVIDIA training after moving, upgrading or deleting an older portable release.

- Before verifying the GPU, the app refreshes the saved CUDA environment using the current release's Python runtime.
- Repairs the old-folder references that caused errors such as `No Python at ...nam2zoom-v1.2.0...`.
- Existing CUDA packages and the remembered CPU/GPU choice are retained. Repairing the folder references does not download CUDA again.
- Includes the CPU/NVIDIA choice before the first Windows build and the **Training device…** button introduced in v1.2.1.
- The repair was verified locally against an existing CUDA environment pointing to a deleted release folder, with successful RTX 3060 detection afterward. Regression coverage checks that repair runs before the CUDA launcher.

Extract the complete release ZIP into a new folder and run `nam2zoom.exe` on Windows. Older release folders are not required. If CUDA has never been installed, select **Training device… → Enable NVIDIA GPU…**; initial setup downloads several GB and requires a compatible NVIDIA driver. CPU training remains available.

> [!WARNING]
> **The macOS version remains untested on real hardware, including USB-MIDI transfers.** macOS training uses CPU; MPS remains disabled. The macOS app is unsigned and unnotarized. CI checks do not establish safe pedal transfers or reliable hardware operation.

Before hardware testing, keep full backup enabled, disable autosave and select a stock patch. Test N2Z alone in an unsaved patch at low volume before adding effects. Saved-patch recall, reboot behavior and long sessions need separate checks. Keep USB and power connected throughout transfers. After a failure, preserve logs and follow the bundled safety instructions before retrying or power-cycling. Custom effects can cause crackling, overflow, freezing or permanent device failure.
